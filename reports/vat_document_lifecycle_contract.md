# 부가세 원본 효력 확인 자료의 선택 계약

`vat_document_lifecycle_v1`은 원본 발급 기관의 확인을 받아 인계 담당자가 기록한 최종 효력을 선택한다. `valid` 원본을 기존 `vat_document_reconciliation_v1`에 전달하고 기존 VAT 계산 엔진을 그대로 실행한다. 실제 공급과 실행 지급은 변경하지 않는다.

이 계약의 `C_DOCUMENT_LIFECYCLE_SELECTION`은 합성 업무 자료의 선택 규약이며 `verified: false`로 등록한다. 취소의 적법성이나 세액공제 기한을 새로 판단하는 정부 법규가 아니다. 원본 효력의 취소를 실제 공급의 취소나 지급 환불로 해석하지 않는다. 과거 신고의 경정도 지원하지 않는다. 최종 프로젝트 범위는 Batch 1과 Batch 2의 총 2,400개다.

## 집필 전제

각 문항의 `scope_note`와 관련 상태 확인 자료에 아래 전제를 명시한다. 프로그램이 이 문장을 분석하여 적법성을 판단한다는 뜻은 아니다.

> 모든 원본의 유효 또는 취소 상태는 발급 기관 확인을 거쳐 적법하게 최종 확정되었다. 실제 과세 공급과 실행 지급은 그대로 존재한다. 필요한 증빙 보관과 수령명세서 제출 요건을 충족한다. 처리일은 자료 대조 기준일이며 법정 세액공제 기한을 뜻하지 않는다.

취소 원본에 표시된 과거 오기 금액은 보존한다. 유효 대체 원본의 금액은 실제 공급 또는 참조 지급과 일치해야 한다. 공급 취소와 환불 또는 다른 공급일의 지급을 자료에 섞지 않는다. 원본 발급일은 기존 계약처럼 실제 공급일과 같아야 한다.

## 입력과 선택

기존 문서 대조 계약의 신고자 및 공급과 지급 및 원본과 활동 필드를 유지한다. `source_contract`를 `vat_document_lifecycle_v1`으로 바꾸고 다음 두 필드를 추가한다.

| 필드 | 의미 |
| --- | --- |
| `processing_date` | 엄격한 ISO 날짜인 인계 자료 대조 기준일 |
| `document_status_records` | 원본마다 최종 확인 상태를 기록한 목록 |

상태 행의 필드는 아래 네 개와 정확히 같아야 한다.

| 필드 | 의미 |
| --- | --- |
| `document_id` | 보존 원본의 고유 번호 |
| `state` | `valid` 또는 `revoked` |
| `confirmed_on` | 발급일 이상이며 처리일 이하인 엄격한 ISO 날짜 |
| `replaces_document_id` | 같은 실제 공급과 같은 유형 및 지급 참조를 가진 취소 원본 번호. 대체 관계가 없으면 `null` |

상태 기록은 모든 보존 원본의 ID 집합과 정확히 일치해야 한다. 같은 ID에 정확히 같은 원본이나 상태 객체를 재전달하면 한 번만 읽는다. 금액이나 상태 및 확인일이 다른 객체는 충돌로 거절한다. 원본 상태가 없거나 원본 없는 상태 기록이 있으면 거절한다.

처리일에 7월 25일 또는 특정 연도의 상한을 두지 않는다. 검사하는 관계는 `원본 발급일 <= confirmed_on <= processing_date`뿐이다. 처리일 이후 상태를 선택하거나 발급 전에 확인되었다고 주장하는 자료는 거절한다.

대체 관계는 `valid` 원본에서 다른 `revoked` 원본으로만 연결된다. 대체 원본의 확인일은 취소 원본 확인일 이상이어야 한다. 거래 ID와 증빙 유형 및 지급 ID가 모두 같아야 한다. 자기 참조와 존재하지 않는 대상 및 순환 관계는 거절한다. 유효 원본을 대체 대상으로 삼거나 취소 원본이 다른 원본을 대체한다고 적어도 거절한다. 하나의 취소 원본을 두 유효 원본이 대체하면 모순으로 거절한다. 대체 관계는 필수는 아니며 상태 확인만 있는 취소도 지원한다.

## 취소 자료도 검증하는 범위

모든 원본에 기존 exact 필드를 요구한다. ID와 실제 거래 및 지급 참조를 확인하고 실제 공급일과 원본 발급일이 같은지 검사한다. 금액은 양의 정수이며 표시 기준과 10% 세액이 정확히 나뉘어야 한다. 세액을 별도 표시했다면 자신의 원본 금액에서 구한 세액과 `stated_vat`가 같아야 한다. 표시가 없으면 세액은 `null`이어야 한다. 세금계산서에는 지급 참조가 없고 별도 세액 표시가 있어야 한다. 카드와 현금영수증은 실제 지급 방법과 일치해야 한다. 일반 영수증과 장부는 적격 세액 표시를 주장할 수 없다.

취소 원본은 과거 금액 오기를 보존할 수 있으므로 실제 공급 또는 지급 금액과의 일치를 요구하지 않는다. 이 예외는 자기 원본 금액의 세액 계산과 날짜 및 거래와 지급 참조 검사를 면제하지 않는다. 선택된 `valid` 원본에는 기존 문서 대조 계약의 실제 금액 일치 조건을 그대로 적용한다. 따라서 유효 세금계산서는 전체 실제 공급을 덮고 유효 지급 증빙은 실제 지급 금액과 일치한다.

활동의 `document_ids`는 취소 원본까지 포함한 해당 구매의 전체 보존 원본 집합과 정확히 같아야 한다. 선택 전에 기존 활동 interpreter로 모든 연결과 날짜 및 활동 내용을 검증한다. 이 선검사의 임시 행은 실제 공급 금액을 사용하므로 취소 원본 오기 금액으로 활동을 판단하지 않는다. 매출에 구매 활동을 붙이거나 존재하지 않는 문서와 활동을 넣으면 선택 과정에서 지워서 통과시키지 않는다.

선택 후 활동의 문서 집합을 유효 원본만 남기도록 좁히고 기존 문서 대조 계약을 호출한다. 매입에 유효 원본이 하나도 없으면 거절한다. 유효한 일반 영수증이나 장부가 남으면 실제 매입세액을 유지하되 적격성 없는 원본의 공제는 기존 엔진대로 0원이 될 수 있다. 부분 매입 지급 증빙에는 여전히 유효한 전체 세금계산서가 필요하다. 효력 선택으로 부분 매입 공제를 새로 허용하지 않는다.

`purpose`와 `business_related` 등 기존 파생 결과는 재귀적으로 거절한다. 선택 ID와 제외 ID 및 대체 관계 같은 사전 계산 선택 결과도 입력에 넣을 수 없다. 원자료는 호출 전후에 바뀌지 않는다.

## 계산 인터페이스와 trace

권장 통합 진입점은 `rules.c_vat.document_lifecycle.calculate(source)`다. 기존 VAT 답의 11개 필드를 반환하며 trace는 다음 순서다.

1. `C_DOCUMENT_LIFECYCLE_SELECTION`: 전체 원본과 최종 상태 및 처리일과 활동을 기록하고 선택 ID 및 제외 ID와 명시적 대체 관계를 출력한다.
2. 기존 `C_DOCUMENT_RECONCILIATION`: 선택된 증빙과 실제 공급 및 지급의 대조를 기록한다.
3. 기존 VAT 계산 엔진의 법정 계산 trace.

`select(source)`는 검증한 기존 문서 대조 계약 입력과 선택 trace를 반환한다. `interpret(source)`는 기존 VAT 엔진 입력을 반환한다. `derivation_trace(source, normalized=None)`는 선택 trace 한 개를 반환한다. 전체 계산 trace를 받으려면 `calculate`를 사용한다.

원본과 상태 및 지급의 배열 순서를 바꾸거나 동일 객체를 재전달해도 답과 전체 trace가 같다. 내부 정렬은 ID에 따라 결정하며 활동 집합도 기존 문서 대조 계약의 정렬 규약을 따른다.

## 독립 수기 검증

새 계약 시험 56개와 기존 Batch 1 C300 답 및 trace 고정 SHA 시험 1개가 통과했다. 두 Python 파일의 Ruff 검사와 포맷 검사도 통과했다. 기존 VAT 모듈을 수정하지 않았다. 실제 PDF와 XLSX 및 HWPX를 통한 통합 검증은 루트가 별도로 수행한다.

| 실제 자료 관계 | 수기 기대값 |
| --- | --- |
| 실제 매출 1,100,000원. 카드 지급 440,000원. 미발급 은행 지급 220,000원. 550,000원 오기 카드 원본은 취소하고 440,000원 대체 원본을 선택 | 전체 매출세액 100,000원. 발급 공제 5,720원. 납부 94,280원. 미수 440,000원 |
| 실제 업무 구매 및 카드 지급 각 550,000원. 미표시 카드는 취소하고 세액 50,000원을 별도 표시한 대체 카드를 선택. 일반 영수증도 보존 | 실제 매입 VAT와 공제 각 50,000원. 대체 카드를 취소하면 실제 VAT는 유지하며 공제 0원과 불공제 50,000원 |
| 매출 A 1,100,000원의 부분 카드 440,000원과 취소된 전체 전자. 매출 B 550,000원의 부분 현금영수증 110,000원. 연간 공제 잔여 6,000원 | 선택 발급액 550,000원의 비율 공제는 7,150원이며 실제 공제 6,000원. A 전자를 유효로 바꾸면 B만 남아 공제 1,430원 |

시험은 상태 범위와 날짜 및 객체 충돌을 거절한다. 취소 원본의 잘못된 자기 세액과 다른 거래 지급 참조도 거절한다. 유효 원본에 오기 금액 예외를 전파하지 않는지 확인한다. 원본 전체 활동 연결과 모든 구매 원본 취소 및 부분 매입의 기존 제약도 검증한다. 모두 취소된 매출은 실제 공급을 보존하며 발급 공제만 0원이 된다.

기존 C300 답 및 trace의 합성 고정 SHA는 `4b63a47229a4c6f28482f70ab816ef569c31f9b063aca9ec10cb6bcf28f6e9f3`로 유지된다. 이 검증은 공개 Batch 1의 계산 보존이며 신규 문항의 독창성이나 전문가 검토를 대신하지 않는다.
