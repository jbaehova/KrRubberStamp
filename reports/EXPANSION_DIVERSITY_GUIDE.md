# 1,650문항의 개별 집필과 의미 다양성 검수 기준

이 기준은 완료된 Batch 1의 원고 1,200개와 현재 네 분야의 계산 엔진 및 원자료 연결 계약을 기준으로 작성했다. Batch 2 작성 중 원고는 열지 않았다. 기존 사례를 비교 대상으로 제시하는 문서이며 새 문제를 자동 생성하는 유형표가 아니다. 기존 1,200문항 전체가 서로 다른 의미 구조라는 승인도 아니다.

## 문항을 직접 쓴다는 기준

저자는 한 문항의 업무 요청과 사실 및 증빙 배치를 직접 결정한다. 계산기는 그 원고의 답을 계산하고 입력 문서 복원을 확인하는 데 사용한다. 제목이나 금액을 바꾸어 원고 본문을 채우는 반복 루프를 사용하지 않는다. 같은 엔진 규칙을 다시 사용하는 것은 가능하지만 그 규칙을 적용해야 할 자료 관계와 실제 업무 판단의 차이를 설명해야 한다.

새 원고마다 가장 가까운 기존 문항을 먼저 찾아 다음 세 가지를 함께 비교한다.

1. 무엇을 결정해야 하는가: 요청한 답안 필드와 실제 마감 목적.
2. 어떤 기록을 연결하는가: 사람이나 거래 식별자와 날짜, 승인 상태, 문서 표지 및 행의 귀속.
3. 연결 결과를 어떻게 선택하거나 합산하는가: 제외 및 포함의 근거와 합산 단위, 상한과 후속 계산의 관계.

세 가지가 같고 금액이나 회사명 및 날짜의 표기만 달라졌다면 재집필한다. 같은 결과 필드라는 이유만으로 탈락시키지는 않는다. 반대로 답안 필드 하나를 추가하거나 결과 칸을 일부 삭제해도 기존 판단 골격이 그대로면 새 문항으로 인정하지 않는다.

문서 개수나 형식 변경은 다양성 근거가 아니다. PDF를 XLSX로 바꾸거나 동일 증빙을 둘로 나누어도 같은 원자료를 같은 규칙으로 선택한다면 동일한 문제다. 원고의 경계값을 조금 이동하는 것만으로 이미 존재하는 경계 사례와 다른 업무가 되지는 않는다.

## 검수자가 실제로 확인할 것

- 가까운 기존 문항의 번호와 결정적인 자료 접점을 적는다. “다른 업종”이나 “금액이 다름”은 차이 설명으로 쓰지 않는다.
- 새 원고의 중심 판단을 하나씩 원자료 경로에 연결한다. 문장에 등장하는 예외가 실제 요청 답에 어떻게 작동하는지 확인한다.
- 중심 원자료를 바꾼 유효한 반사실을 직접 설계한다. 어떤 요청 답이 바뀌거나 유지되는지 먼저 설명하고 계산 결과와 비교한다.
- 제외 자료만 변경했을 때 유지되어야 하는 답도 확인한다. 유지되는 이유가 다른 규칙의 상한 때문인지, 집계 대상 밖이기 때문인지 구분한다.
- 실제 입력에 선택 결과를 써 놓지 않는다. 공제 가능 여부와 집계 대상 목록 및 총 근로분처럼 문제의 중심 판단을 대신하는 결과를 원자료에 추가하면 고친다.
- 원고가 주장하는 모든 예외를 장식으로 남기지 않는다. 중심 예외가 요청 답에 드러나지 않으면 해당 예외를 빼거나 업무 요청과 수치를 다시 직접 작성한다.

반사실은 입력 계약이 허용하는 사실을 함께 바꿔야 한다. 총급여와 근로소득금액이 서로 모순되는 가족 자료나 겹치는 차량 등록기간을 만들고 답이 바뀌었다고 기록하면 의미 검증이 아니다. 부적합 입력의 거절 검사는 정상 문항의 반사실과 별도로 기록한다.

oracle 정답 일치와 null 실패는 파이프라인 확인이다. 문항별 관계가 다른지, 모든 법적 요건이 적절한지 확인하는 사람의 비교를 대신하지 않는다. 자동 의미 다양성 점수나 독립 전문가 승인으로 표현하지 않는다.

### 현재 계약 안에서 직접 검토할 관계 축

사람별 자격과 지출별 요건을 분리해서 다룬다. [A042](../authored/batch_1/A_yearend/cases_004_053.json)의 장애인 형제는 일반 가족 공제의 소득요건과 적격 특수교육비의 경로가 다르다. 소득 있는 부모를 배우자로 치환하는 것만으로는 새 관계가 아니다. 어떤 지출이 같은 사람의 자격에 의존하고 어떤 지출이 다른 요건을 따르는지 요청 답에서 보여야 한다.

학비는 학생 ID와 기관 종류 및 실제 부담자의 연결을 구분한다. [A272](../authored/batch_1/A_yearend/cases_254_300.json)는 같은 학생의 납부를 부부의 실제 부담분으로 나눈다. [A276](../authored/batch_1/A_yearend/cases_254_300.json)는 두 장애 학생의 일반 학부와 적격 특수교육을 서로 다른 한도로 처리한다. 같은 총 교육비에 다른 직장이나 학교 이름을 붙이지 말고 부담과 한도의 귀속이 달라지는 이유를 직접 설계한다.

근무 기간은 증빙 종류별로 확인한다. [A177](../authored/batch_1/A_yearend/cases_154_203.json)는 퇴직 뒤 은행 이자와 보험 납부를 제외한다. [A275](../authored/batch_1/A_yearend/cases_254_300.json)는 같은 봄학기라도 입사 전 선납과 입사 후 추가 납부를 구별한다. 수업 기간이나 연간 증명 기간이 실제 지급일을 대신한다는 설명을 만들지 않는다.

상한 때문에 최종 세액이 유지되는 관계는 중간 결과를 함께 요청할 때만 판단이 보일 수 있다. [A251](../authored/batch_1/A_yearend/cases_204_253.json)는 카드 공제와 종합한도 초과액이 바뀌어도 과세표준이 유지된다. 상한에 막혀 아무 요청 답도 바뀌지 않는 가족 자료를 중심 예외처럼 설명하지 않는다.

주택은 주소와 세대 주택 목록 및 이자 지급일을 구별한다. 나머지 취득 및 차입 요건은 현행 계약의 확인 전제를 지킨다. [A253](../authored/batch_1/A_yearend/cases_204_253.json)의 만기 상환 뒤 매도 사례를 조기상환의 법적 판단 문제로 확대하지 않는다.

정규와 추가 근로의 기본 대가 및 가산을 구분한다. [B224](../authored/batch_1/B_payroll/cases_204_253.json)는 정규 교대의 야간과 추가 작업의 야간을 함께 보지만 연장 대가는 추가 작업에만 적용한다. [B210](../authored/batch_1/B_payroll/cases_204_253.json)은 월급에 포함된 휴일 기본 대가를 다시 더하지 않아도 정규 교대의 야간 가산이 남는다.

2026년 달력과 재직 범위를 실제 최종 승인 기록에 대조한다. 7월 17일은 현행 기준에서 공휴일이다. 휴일 출동과 기본 유급 대가 및 주휴를 같은 항목으로 섞지 않는다. 단시간 추가 근로의 전제와 통상시급 제수도 계약에서 확인한다. 지원하지 않는 소급 보험 정산이나 새로운 수당 제도를 다양성 목적으로 추가하지 않는다.

표시 상호와 법적 청구 주체를 구분한다. [C230](../authored/batch_1/C_vat/cases_204_253.json)은 서로 다른 간판 두 곳이 같은 청구 ID를 사용하고 세 번째 간판만 별도 간이 공급자다. 공급자의 효력기간도 실제 공급일에 연결하며 현재 상태를 이전 거래에 소급하지 않는다.

장소가 다르다는 이유로 업무 관계를 단정하지 않는다. [C208](../authored/batch_1/C_vat/cases_204_253.json)은 물품 반입과 외주 서비스의 장소가 달라도 둘 다 과세 설치 업무에 연결된다. 활동의 실제 사용 대상과 참여자 조직을 기록한다. 사업장이라는 단어만으로 `business_related`를 미리 부여하지 않는다.

공급일과 대금 지급일 및 등록 효력일을 구분한다. [C225](../authored/batch_1/C_vat/cases_204_253.json)는 같은 대여차 정비라도 작업 완료일로 신고 기간을 나눈다. [C284](../authored/batch_1/C_vat/cases_254_300.json)는 독립 장치 인도와 별도 용역 완료가 선불 및 후불 순서와 다르다. 한 공급을 임의로 여러 거래로 쪼개서 시간 관계를 만들지 않는다.

서로 다른 공제 제한이 어떤 요청 답을 바꾸는지 구분한다. [C283](../authored/batch_1/C_vat/cases_254_300.json)의 연간 발행 공제 상한과 [C240](../authored/batch_1/C_vat/cases_204_253.json)의 납부 고지 차감은 다른 단계다. 고지 납부와 이전 예정신고 납부를 같은 선납액으로 다시 차감하지 않는다.

활동 계약은 대표 혼자 먹은 식사와 고객 선물을 판단하지 않는다. 고객과 가족이 섞인 식사도 지원하지 않는다. 과세와 면세에 공통으로 사용하는 매입의 안분은 범위 밖이다. 자동차 법적 분류와 산출 활동의 과세 여부는 확인된 출발 사실이다. 새로운 자유 문장 법률 해석을 지원하는 것처럼 문항을 쓰지 않는다.

### 현재 계약 안에서 직접 검토할 관계 축

이 분야는 결과 종류와 선택 계약이 특히 좁다. 업종과 물품 이름을 바꾸기 쉽다는 점 자체를 검수 위험으로 본다. 문서 수를 늘리는 것만으로 난이도나 새 의미 관계를 인정하지 않는다.

표지 연결은 무엇이 달라지는지에 따라 검토한다. [D276](../authored/batch_1/D_extract/cases_254_300.json)은 별첨이 물려받는 세금 포함 조건이 공급가액과 세액을 바꾼다. [D283](../authored/batch_1/D_extract/cases_254_300.json)은 별첨 귀속을 다른 표지로 바꾸면 전체 금액이 유지되어도 업체별 지급액이 바뀐다. 귀속 판단이 업체 지급에만 보이는 원고에서 `grand_total`만 요청하면 중심 판단을 검증할 수 없다.

구매 근거와 가격 참고자료를 구분한다. [D281](../authored/batch_1/D_extract/cases_254_300.json)은 두 수정 견적과 실제 최종 발주의 품목 및 수량이 다르며 실제 인수 사건이 있는 발주만 집계한다. 마지막 파일을 자동 선택하는 업무로 설명하지 않는다. 미수령 주문과 출고 전 취소의 관계도 사건에 기록된 범위 안에서 다룬다.

가격 단위와 실제 지출 단위는 따로 검토한다. [D285](../authored/batch_1/D_extract/cases_254_300.json)는 부가세 포함 행별 원 미만 처리와 전체를 한 번 나누는 처리가 다르다. [D300](../authored/batch_1/D_extract/cases_254_300.json)은 업체별 지급의 합산 단위와 품목별 비교 단위가 다르다. 세액 역산으로 구한 개당 비교 단가와 수량을 곱한 행 전체의 공급가액을 혼동하지 않는다.

엔진의 최저가 기준은 포함 단가를 환산한 정수 공급가액 단가다. 실제 납품 없는 가격은 후보가 아니다. 단위 변환이나 규격의 의미 추정 및 업체 약칭 추정은 추가하지 않는다. 같은 문서번호의 상충 내용은 임의로 최신본을 고르는 문제가 아니라 계약 거절 대상이다. 부분 인수와 반품 및 수정계산서 정산은 기존 `extract_evidence_v1` 계약 밖이다.

## 추가 선택 계약의 적용 범위

`yearend_pay_statement_v1`은 제출 증명서의 직원과 사용자 및 지급기간을 연결해 최고 발급 수정본을 선택한다. 선택한 급여와 비과세 및 독립된 국세와 지방세 합계가 후속 공제 요건이나 정산 답에 영향을 주어야 한다. 같은 기존 공제 사례에 증명서 외형만 씌운 경우는 새 업무로 인정하지 않는다.

`payroll_bank_reconciliation_v1`은 완전한 직원 월급과 실제 이체를 연결한다. 직원 간 과지급과 미지급을 전체 잔액으로 상계하면 개인별 지급 상태를 잃는 경우처럼 요청한 답에 실제 귀속 판단이 남아야 한다. 직원 및 보험 부과월별 명세는 완전한 한 달이며 인위적으로 나눠 계산하지 않는다. 같은 실제 지급일의 현금 대조만 지원한다.

`vat_document_reconciliation_v1`은 전체 공급과 부분 발급을 구분하고 전체 적격 매입 증빙의 보완을 지원한다. 결제 행을 늘렸다는 이유만으로 새 관계를 주장하지 않는다. 전체 공급세액과 실제 발행 공제 기초액이 다르게 움직이거나 활동 귀속과 증빙 보완이 서로 다른 요청 결과를 바꾸는 연결을 검토한다. 부분 매입 안분은 지원하지 않는다.

`extract_fulfillment_v1`은 포장 발주와 낱개 인수 및 반품과 실행 지급을 대조한다. `extract_procurement_v1`은 필요 수량과 판매 포장 및 배송과 납기 조건의 실제 구매비를 비교한다. 두 계약은 문항에 명시한 사적 산술 약정이다. 미지원 수정세금계산서의 법적 판정이나 실제 공급일 판단을 수행하지 않는다.

## 롤링 집필과 인계

저자는 묶음 인계 때 각 문항의 가까운 기존 번호와 새로운 업무 판단의 차이를 남긴다. 다음 저자는 완료되어 고정된 원고까지 비교 범위를 넓힌다. 작성 중인 다른 저자의 소유 파일은 열거나 수정하지 않는다.

비교 기록은 재집필을 결정할 근거이며 기계적 승인표가 아니다. 신규 원고의 총 개수와 난이도 및 계산 검증을 확인한 뒤, 가까운 구조의 문항은 요청 답과 원자료 접점을 나란히 읽는다. 반복이 확인되면 현행 법지원 범위를 유지하며 해당 문항을 직접 다시 쓴다. 지원하지 않는 법률 시나리오를 억지로 추가해 문항 수를 채우지 않는다.
