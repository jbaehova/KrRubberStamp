# 최종 1,650문항 공개 범위

최종 공개 범위는 기존 Batch 1의 1,200문항과 Batch 2의 450문항이다. 데이터셋 이름은 `KrRubberStamp-1.65K`이며 누적 내보내기는 `exports/upto_2`를 사용한다. Batch 3과 Batch 4는 없다.

| 분야 | Batch 1 | Batch 2 | 최종 합계 |
|---|---:|---:|---:|
| A_yearend | 300 | 100 | 400 |
| B_payroll | 300 | 100 | 400 |
| C_vat | 300 | 100 | 400 |
| D_extract | 300 | 150 | 450 |
| 합계 | 1,200 | 450 | 1,650 |

| Batch 2 분야 | easy | medium | hard | 허용 문항 ID |
|---|---:|---:|---:|---|
| A_yearend | 30 | 45 | 25 | A001부터 A100 |
| B_payroll | 30 | 45 | 25 | B001부터 B100 |
| C_vat | 30 | 45 | 25 | C001부터 C100 |
| D_extract | 45 | 68 | 37 | D001부터 D150 |
| 합계 | 135 | 203 | 112 | 450문항 |

기존 문서 추출 150문항을 유지하므로 분야별 최종 수량은 균등하지 않다. 최종 난이도 합계는 easy 495개, medium 743개, hard 412개다. Batch 1의 분야별 90/135/75 구성은 바꾸지 않는다.

`KrRubberStamp/release_scope.py`에 수량과 ID 범위를 모았다. 완성본 빌드와 내보내기는 같은 검사 함수를 사용한다. 수량만 맞추고 ID를 바꾸거나 동일 ID를 중복하는 경우에도 실패한다. 편집용 미리보기는 기존대로 부분 집필 원고를 허용한다.

Hugging Face 게시에는 정확히 1,650개의 개별 집필 문항과 배치 [1, 2]를 요구한다. 현재 원고로 정답 및 trace를 다시 계산하고 문항 ID와 스키마 및 실제 입력 파일을 확인한다. 원고별 승인 SHA256과 승인된 ID 집합을 대조하며 승인 원고에 별도 문항이 들어 있는 경우도 거절한다. JSONL의 현재 해시와 검증 및 가짜 솔버 측정, 보고서의 task-set 표시를 확인한다. 공개 데이터 및 원고 경로에는 JSONL이 참조하지 않는 별도 문항 파일을 포함할 수 없다. 기존 비공개 파일과 심볼릭 링크 차단 및 고정 원격 revision 검사를 유지한다.

데이터카드는 실제 분야별 수량을 적는다. 최종 이름의 1.65K를 한 자리 소수로 반올림하지 않는다. 배치 보고서는 Batch 2의 실제 450문항을 기준으로 쓰며 사람 검토 대기열은 분야별 15문항씩 총 60문항을 유지한다.

이번 범위 변경 검증에서 관련 테스트 71개가 통과했다. Ruff 검사와 포맷 검사도 통과했다. 기존 Batch 1의 1,200문항을 현재 원고에서 복구해 gold와 trace의 바이트를 대조했으며 task-set SHA256은 아래 값으로 유지되었다.

`f52c5b067719881279f96d39358132cb01955090905f1305704d9a59050f68ac`

이 기록은 공개 범위와 게이트 변경을 검증한 결과다. Batch 2의 모든 원고를 승인하거나 1,650문항 전체의 최종 배포 검증을 완료했다는 뜻은 아니다. 최종 원고 승인과 전체 문서 검증 및 누적 내보내기 확인은 별도 완료 절차를 따른다. 독립 전문가 검토는 대기 상태이며 이번 작업에서 모델 API나 실제 게시를 수행하지 않았다.
