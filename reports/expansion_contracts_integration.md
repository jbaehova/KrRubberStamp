# 2,400문항 확장의 선택적 원자료 대조 통합

개별 집필자가 실제 문서의 관계를 문제로 만들 수 있도록 원자료 대조 계약을 추가했다. 기존 1,200문항의 사실과 정답을 바꾸거나 새 문항을 자동 생성하지 않는다.

| 선택적 계약 | 대조하는 관계 | 범위 제한 |
|---|---|---|
| `yearend_pay_statement_v1` | 직원과 사용자 및 지급기간별 발급 수정본 선택 후 연간 급여와 국세 및 지방세 합산 | 2025년의 채택 기간을 검증하며 같은 사용자의 기간 중복은 거절 |
| `payroll_bank_reconciliation_v1` | 완전한 직원 월 급여명세와 실제 실행 이체 | 같은 직원의 같은 보험 부과월 중복 및 서로 다른 실제 지급일 거절 |
| `vat_document_reconciliation_v1` | 실제 공급 전체와 당일 결제 및 개별 증빙의 금액 | 부분 매입세액 안분과 다른 날 지급 및 발급은 범위 밖 |
| `extract_procurement_v1` | 판매 포장과 최소 주문량 및 배송과 납기 조건의 실제 구매비 | 문항에 명시한 사적 약정에 따라 선택하며 세법 판정 아님 |
| 월세 계약자 원자료 | 계약자 식별번호를 직원 및 기본공제 가족의 인적관계에 연결 | 계약자 적격 결론을 원자료에 함께 넣으면 거절 |

새 선택적 계약은 업무 자료의 합성 내부 처리 규약이다. 정부가 승인한 추가 법률 규정으로 주장하지 않으며 출처의 `verified: false`를 유지한다. 기존 법률 계산은 기존 엔진과 출처를 사용한다. 전체 출처는 75개이며 독립 공식 수치 예시로 확인한 항목은 30개다.

## 통합 검증

전체 테스트 908개가 통과했다. 세금 및 임금 계산의 기존 회귀검증과 선택적 계약의 엄격한 형식 및 날짜와 ID 연결 검사를 포함한다. 새 A와 B 및 C 계약을 공개 registry로 연결하여 각 PDF와 XLSX 및 HWPX의 실제 파일에서 중첩 원자료를 복원한 9개 시험도 통과했다.

XLSX 원본 셀을 실제로 편집한 결과도 확인했다. A의 기납부 지방세를 100,000원 늘리자 국세는 유지되고 최종 정산 합계가 100,000원 줄었다. B의 기본급을 100,000원 늘리고 보험 통지액을 유지하자 실지급액과 미지급액이 각각 100,000원 늘었다. C의 실제 카드 결제 및 발급 원본을 55,000원에서 44,000원으로 함께 줄이자 전체 매출세액 10,000원은 유지되고 발행 공제가 715원에서 572원으로 줄었다. 추출 맵에 정답이나 원본 금액을 저장해 계산하는 방식이 아님을 검증했다.

기존 원자료 계약에 새 VAT 내부 파생 필드인 `issued_receipt_gross` 또는 `documented_input_vat`를 넣으면 공개 registry가 거절하는 회귀검증도 추가했다.

공개 Batch 1의 전체 1,200문항을 현재 엔진으로 다시 대조했다. 집필 원고의 provenance와 정답 및 스키마와 trace가 모두 유지됐다. 문항 집합 SHA256은 `f52c5b067719881279f96d39358132cb01955090905f1305704d9a59050f68ac`이다. [불변성 증거](expansion_contracts_legacy_integrity.json)에 결과를 기록했다.

검증 과정의 모델 API 호출은 0회다. 위 결과는 엔진 통합 검증이며 작성 중인 Batch 2 문항의 의미 중복 검토 통과를 대신하지 않는다.

다품목 `extract_cart_procurement_v1`도 공개 registry에 통합했다. 구매 요청 PDF와 공급사 배송 XLSX 및 품목 견적 HWPX를 실제로 복원하여 2,090원 전체 구매 선택을 확인했다. 배송 원본 셀을 400원에서 1,000원으로 바꾸자 다른 공급사의 2,530원 전체 조합으로 선택이 바뀌었다. 선택 계약의 전체 조합 검증을 단품 최저가와 별도로 확인했다.

## 최종 확인된 원본 효력 대조

`vat_document_lifecycle_v1`은 적법하게 최종 확인된 유효 및 취소 원본과 대체 참조를 읽은 뒤 기존 공급과 실제 지급 대조 및 부가세 계산에 연결한다. 원본 취소의 적법성이나 발급 기한 및 공급 취소와 과거 신고 경정은 판정하지 않는다. 공급과 실제 지급은 유지한다. 상세 계약은 [원본 효력 대조](vat_document_lifecycle_contract.md)에 있다.

새 모듈의56개 시험과 root의 PDF/XLSX/HWPX 실제 복원3개가 통과했다. XLSX의 전체 전자 원본 상태만 유효에서 취소로 바꾸면 실제 공급세액10,000원은 그대로이고 부분 카드 발행 공제가0원에서715원으로 바뀐다. root 전체991개 시험도 통과했고 현재 엔진으로 기존1,200개 원고와 물리 자료 및 정답과 schema와 trace를 다시 대조해 같은 task-set SHA를 확인했다.

## 독립 신고의 현금 대조와 창고별 수량 대조

`vat_bank_reconciliation_v1`과 `extract_inventory_snapshots_v1`을 공개 registry에 연결했다. 각 계약의 엄격한 원자료 검사와 독립 수계산을 포함한 root 전체 1,165개 시험이 통과했다. 두 계약의 PDF와 XLSX 및 HWPX 실제 원본 편집 6개 시험도 통과했다. 은행 이체8,000원을9,000원으로 바꾸자 신고 계산은 유지되고 대조 잔액2,000원이1,000원으로 바뀌었다. 창고 이동9개를8개로 바꾸자 주문과 조직 전체 재고18개는 그대로이고 지정 창고의 부족1개가0개로 바뀌었으며 창고별 잉여 합계인 가용수량은4개에서3개로 바뀌었다. 추출 맵과 기존 gold 및 trace 파일은 수정하지 않았다.

원본 효력 계약의 개별 출처 누락도 보완했다. 현재75개 출처 중 공식 수치 예시로 확인한 항목은30개이고 나머지45개는 `verified: false`다. 기존 Batch1 전체1,200문항의 원고 및 실제 자료와 정답 및 trace를 다시 대조했으며 동일한 task-set SHA를 유지한다. 모델 API 호출은0회다.
