# 부가세 공급과 지급 및 개별 증빙의 대조 계약

`vat_document_reconciliation_v1`은 완료된 실제 공급의 전체 금액과 같은 날 실행한 지급 및 개별 증빙의 금액을 분리한다. 공급 한 건의 카드 일부와 미발급 현금을 각각 별개 공급으로 만들지 않는다. 매입의 불완전 카드와 전체 적격 세금계산서는 증빙별 세액 표시가 달라도 동일 공급을 기록할 수 있다. 기존 `vat_activity_evidence_v1`의 활동과 공급자 및 차량 대조를 재사용한다.

이 계약의 `C_DOCUMENT_RECONCILIATION`은 업무 자료의 연결 규약이다. 정부가 승인한 법규나 공식 숫자 예제로 주장하지 않으며 `verified: false`로 등록한다. 자유 서술에서 공급시기나 업무 관련성 또는 적법한 발급 여부를 새로 판단하지 않는다.

## 확정한 범위

일반과세자의 2026년 제1기 신고이며 국내 10% 과세 재화와 용역의 확정 공급만 지원한다. 모든 금액은 공급가액 및 10% 세액이 원 단위 정수로 정확히 나뉘어야 한다. 실제 공급일은 자료로 주어진 사실이다. 지급 실행일과 증빙 발급일은 그 공급일과 같아야 한다. 과세기간 밖의 실제 공급도 동일 조건으로 기록할 수 있고 기존 엔진이 기간에서 제외한다.

`scope_note`에 적법하게 보관한 증빙이며 필요한 신용카드매출전표 등 수령명세서를 제출한다는 전제를 명시한다. 적격 세금계산서의 다른 법정 기재사항 충족과 공급자의 공식 과세유형 및 차량의 법적 분류는 기존 계약처럼 제공된 사실이다. 그 적법성을 이 필드의 자연어를 읽어서 검증한다고 주장하지 않는다.

매입의 부분 공제는 지원하지 않는다. 부분 지급 증빙은 같은 실제 공급 전체를 덮는 적격 세금계산서가 있을 때만 받아들인다. 이 경우 공제의 범위는 세금계산서의 전체 공급이고 일부 카드 세액들을 임의로 합산하지 않는다. 전체 적격 세금계산서를 제거해서 부분 매입 증빙만 남으면 계약 밖 자료로 거절한다. 전체 금액 카드에 세액 표시가 없고 전체 적격 세금계산서도 없다면 전체 매입세액을 기록하되 공제액은 0원이다.

다른 날의 선수금과 사전 발급 또는 지연 전자 보완은 지원하지 않는다. 하나의 합산 입금으로 서로 다른 실제 공급을 결제하는 다대다 배분도 지원하지 않는다. 반품과 수정세금계산서 및 공급시기 특례와 과면세 공통매입 안분은 지원하지 않는다. 전자세금계산서 발급 자체의 별도 세액공제를 추가하지 않는다.

## 원자료 필드

최상위에 `source_contract`, `supplies`, `payments`, `evidence_documents`를 둔다. `transactions`는 함께 넣을 수 없다. 신고자와 기간 및 공제 이력은 기존 엔진 필드 그대로 사용한다. `taxpayer_type`은 `general`이며 `period_start`와 `period_end`는 각각 `2026-01-01` 및 `2026-06-30`이다. `consumer_facing_business`는 엄격한 불리언이다. `scope_note`는 비어 있지 않은 문장이다.

`business_name`, `business_type`, `prior_year_site_supply_base`, `receipt_credit_previously_claimed`, `prepaid_assessed_vat`가 기존 의미를 유지한다. `prior_declared_vat_paid`도 기존 예정신고 조건에 따른다. `site_year_records`와 `filing_site_id`를 쓰면 선택된 `prior_year_site_supply_base`를 미리 넣지 않는다.

### 실제 전체 공급 `supplies[]`

| 필수 필드 | 의미 |
| --- | --- |
| `transaction_id` | 유일한 실제 공급 번호. 같은 번호의 공급행 중복도 거절 |
| `direction` | `sale` 또는 `purchase` |
| `date` | 실제 공급일인 엄격한 ISO 날짜 |
| `description` | 비어 있지 않은 실제 공급 설명 |
| `amount` | 양의 정수 원. 불리언 및 소수 금액 거절 |
| `includes_vat` | 부가세 포함 여부인 엄격한 불리언 |
| `taxable` | 반드시 불리언 `true` |
| `counterparty_consumer` | 상대방에 대한 자료상 사실인 엄격한 불리언 |

매입에는 `activity_id`가 추가로 필요하다. 공급자 대장이 없으면 공식 사실 `supplier_general`을 불리언으로 제공한다. `supplier_status_records`가 있으면 대신 `supplier_id`를 제공하며 `supplier_general`을 미리 넣지 않는다. 차량 대장을 쓰는 매입은 `vehicle_id`로 연결하고 기존 두 차량 분류 결과를 미리 넣지 않는다. 차량번호를 쓰지 않는 매입에는 기존 `vehicle_subject_excise`와 `vehicle_direct_business` 불리언을 제공한다. 활동 및 차량 대조의 다른 제약은 기존 계약과 같다. 매출 공급에는 이 매입용 추가 필드를 넣지 않는다.

`purpose`와 `business_related` 또는 `issued_receipt_gross` 및 `documented_input_vat` 같은 계산 결과를 원자료에 넣으면 거절한다. `eligible`, `deductible`, `included`, `receipt_base`도 원자료 결과 필드로 허용하지 않는다.

### 실제 지급 `payments[]`

| 필수 필드 | 의미 |
| --- | --- |
| `payment_id` | 실제 지급 실행의 고유 번호 |
| `transaction_id` | 정확히 하나의 실제 공급 참조 |
| `date` | 실제 공급일과 같은 지급 실행일 |
| `amount`, `includes_vat` | 실제 지급액과 표시 기준. 원 단위 정확한 세액 분리 |
| `method` | `card`, `cash`, `bank_transfer` |

지급 합계는 해당 실제 공급의 부가세 포함 총액을 넘을 수 없다. 공급 완료 당일 일부만 지급되어 미수액이 남는 기록도 유효하다. 지급이 없어도 매출 전체 공급은 기록한다. 동일 `payment_id`에 같은 내용을 재전송하면 한 번만 읽는다. 다른 내용이면 거절한다.

### 개별 증빙 `evidence_documents[]`

| 필수 필드 | 의미 |
| --- | --- |
| `document_id` | 실제 증빙 원본의 고유 번호 |
| `transaction_id` | 실제 공급 참조 |
| `date` | 실제 공급일과 같은 발급일 |
| `document_type` | `tax_invoice`, `card_receipt`, `cash_receipt`, `cash_ledger`, `receipt` |
| `amount`, `includes_vat` | 그 증빙이 실제 표시하는 금액과 기준 |
| `vat_separately_stated` | 그 증빙의 세액 별도 표시 사실인 엄격한 불리언 |
| `stated_vat` | 표시가 있으면 그 실제 세액인 정수. 표시가 없으면 반드시 `null` |
| `payment_id` | 카드나 현금 증빙의 실제 지급 참조. 세금계산서는 반드시 `null` |

세금계산서는 해당 실제 공급의 전체 금액을 덮고 세액을 별도로 표시해야 한다. 개별 지급 증빙은 참조한 실제 지급의 거래번호와 공급가액 및 세액 및 총액이 모두 같아야 한다. 카드 전표는 카드 지급을 참조하고 현금영수증은 현금 지급을 참조한다. 장부와 일반 영수증은 실제 지급에 연결하지만 적격 세액 표시를 주장할 수 없다.

동일 원본 ID와 같은 내용의 재전송은 한 번만 읽는다. 다른 내용의 같은 원본 ID는 거절한다. 같은 지급 실행에 서로 다른 카드 또는 현금영수증 발급 원본 두 장이 연결되면 범위가 모호하므로 거절한다. 파일명만 다른 복사본은 원본 ID를 그대로 유지해야 한다.

## 활동 연결과 내부 계산

`operations`와 `activities`는 기존 원자료 계약을 그대로 사용한다. 매입 활동의 `document_ids`는 그 공급에 연결된 실제 `evidence_documents`의 문서번호 집합과 정확히 같아야 한다. 활동의 `transaction_id`와 날짜도 실제 공급과 일치한다. `supplier_status_records`, `vehicle_registry`, `site_year_records`와 날짜별 효력 대조를 모두 재사용한다. 매출만 있는 자료는 활동 및 작업 목록이 비어 있을 수 있다.

`interpret(source)`는 원자료를 바꾸지 않고 기존 VAT 엔진용 복사본을 돌려준다. 공급 전체 금액은 내부 증빙행들에 동일하게 옮기고 원래 부분 발급 금액은 대조 trace에서 보존한다. 이 행들은 기존 거래별 중복 제거를 거쳐 공급세액을 한 번만 집계한다. 발급 증빙이 하나도 없는 매출은 실제 거래번호를 내부 `document_id`의 자리표시자로 사용한다. 이를 실제 발급 원본으로 주장하지 않으며 대조 trace의 `document_ids`는 비어 있고 발급모수는 0원이다.

매출의 `issued_receipt_gross`는 서로 다른 실제 지급에 대해 발급한 카드 및 현금영수증의 부가세 포함 합계다. 실제 공급 총액보다 작을 수 있다. 기존 법규가 세금계산서 중복 및 신고자 자격을 제외한 뒤 공제율과 연간 한도 및 납부세액 한도를 적용한다. 미발급 잔액을 카드 발급액으로 확대하지 않는다.

매입의 `documented_input_vat`는 해당 공급 전체를 덮는 적격 증빙이 있으면 실제 전체 VAT이고 없으면 0이다. 증빙별 세액 표시가 다른 사실은 원자료 충돌이 아니다. 업무 관련성과 접대 및 차량 또는 면세 귀속 제한은 기존 엔진에서 우선 적용한다. 전체 적격 전자가 있어도 가사 지출이나 제한 대상 차량의 세액은 공제하지 않는다.

`derivation_trace(source, normalized)`는 하나의 `C_DOCUMENT_RECONCILIATION` trace 객체를 반환한다. 정렬한 실제 공급과 지급 및 원본 증빙을 기록하고 활동 및 대장 연결도 보존한다. 출력에는 공급가액과 세액 및 총액, 지급 합계와 미수잔액, 발급 합계와 미발급잔액, 전체 적격 매입 증빙 번호 및 파생 내부 필드가 있다. 같은 내용 재전송과 입력 행 순서 변경은 정답과 전체 trace를 바꾸지 않는다. 정답 필드는 기존 VAT 엔진의 11개 필드를 유지한다.

루트의 라우팅 통합은 기존 구조와 같다.

```python
normalized = document_reconciliation.interpret(source)
answer, trace = engine.calculate(normalized)
return answer, [document_reconciliation.derivation_trace(source, normalized), *trace]
```

## 확인한 공식 근거와 적용 시점

2026년 1월 2일 시행본의 [부가가치세법 제46조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0046&lsiSeq=276117&urlMode=lsScJoRltInfoR)는 발급금액 기준과 2026년 우대율 및 한도와 별도 세액 표시 요건의 근거다. 해당 조문의 최근 개정 표시는 2023년 12월 31일이며 2026년 1월 1일에도 이 계산 내용은 같다. 후속 2026년 10월 시행본을 이 신고기간의 근거로 사용하지 않았다. [제38조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0038&lsiSeq=276117&urlMode=lsScJoRltInfoR)는 사업 사용을 위한 매입세액과 공급받은 과세기간의 공제라는 기존 기준을 확인한다.

[국세청 세무 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=239004&mi=40574)는 2026년 발급 공제율 및 한도의 공식 안내다. [국세청 도소매업 신고서 작성사례](https://www.nts.go.kr/comm/nttFileDownload.do?fileKey=95e20f2fcbd5b8094e3899abd6609bc2)는 세금계산서와 카드의 중복 공급을 제외하는 기존 계산 근거다. 아래 소액 대조 예시는 독립 수기 시험이며 공식 예시라고 주장하지 않는다.

업무 및 가사 사용과 고객 식사 및 면세 귀속과 제한 대상 승용차 및 공급자 상태가 전체 적격 증빙보다 우선하는 것도 확인했다. 기존 날짜별 차량 허가와 공급자 대장을 실제로 새 구조에 연결했다. 자료 전체를 직접 보존하고 같은 ID 재전송 및 목록 순서 변경이 정답과 전체 trace를 바꾸지 않는 시험을 포함했다.

기존 Batch 1 C300의 각 엔진 정답과 trace를 정렬된 JSON으로 직렬화한 개별 SHA를 모아 계산한 aggregate SHA256은 변경 전후 모두 `4b63a47229a4c6f28482f70ab816ef569c31f9b063aca9ec10cb6bcf28f6e9f3`이다. 현재 데이터의 `gold.json` 및 `trace.json` 600개 실제 파일도 변경 전후 동일하며 경로별 원본 바이트 SHA를 모은 aggregate SHA256은 `1742236ee2443a6a6ed1ba33aa834e473b969bb39bc694558d7d6cb500670484`이다. 수기 정답을 기존 정답 파일에서 역으로 만들지 않았다.
